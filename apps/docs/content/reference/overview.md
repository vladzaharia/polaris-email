# Reference

The machine-readable surface. Narrative on _why_ the contracts are
shaped this way lives under [Developers](/developers) and
[Operators](/operators).

## REST API

The OpenAPI reference is generated by `docusaurus-plugin-openapi-docs`
from [`openapi/polaris-mail.yaml`](https://github.com/polaris/polaris-mail/blob/main/openapi/polaris-mail.yaml)
on every build. Each tag becomes a sidebar section; each operation gets
its own page with request and response schema panels.

→ **[REST API](/reference/api/polaris-mail-api)**

Reach for it when you want:

- The exact JSON shape of a `Message` field.
- The full list of HTTP error codes returned by an endpoint.
- A canonical request example for HMAC signing.

The narrative on the unified `Message` model lives at
[Developers → Unified model](/developers/messages/unified-model).

## CLI vocabulary

→ **[CLI vocabulary](/reference/cli)** — the four state-change verbs
(`revoke`, `deregister`, `disable`, `delete`), what each targets,
whether it is reversible, and how long propagation takes.

The verb-by-verb workflow tour is at
[Operators → CLI tour](/operators/day-2/cli-tour).

## Errors

→ **[Error catalog](/reference/errors)** — every error code the API
emits, the HTTP status, retryability, and a recovery hint. The
canonical enum is `ErrorCode` in `packages/schema/src/index.ts`; the
HTTP-status mappings are in `services/api/src/errors.ts`.

## Consumer contract

→ **[Consumer contract](/reference/consumer-contract)** — the stability
promises polaris-mail makes you. Read before integrating.

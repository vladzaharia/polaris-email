# Reference

The pages under this section are mechanically generated. They are the
machine-readable surface, not the narrative — the developer and operator
sections cover *how* and *when*.

## REST API

The OpenAPI reference is generated by `docusaurus-plugin-openapi-docs`
from [`openapi/polaris-email.yaml`](https://github.com/polaris/polaris-email/blob/main/openapi/polaris-email.yaml)
on every build. Each tag becomes a sidebar section; each operation gets
its own page with request/response schema panels.

Reach for it when you want:

- The exact JSON shape of a `Message` field.
- The full list of HTTP error codes returned by an endpoint.
- A canonical request example for HMAC signing.

The narrative on _why_ the contract is shaped this way lives under
**For developers → Messages** (lands in the content-migration phases of
PR 12).

## CLI

The `polaris-email` Go CLI's command surface will be documented under
`/reference/cli` in a later phase. The CLI source-of-truth today is the
embedded `--help` output and `apps/polaris-cli/README.md`.

## Errors

A catalogue of every error code the API and CLI emit, with a recovery
playbook for each, will live at `/reference/errors` in a later phase.

## Schema definitions

The unified `Message` schema and its TypeScript / Go bindings are
sourced from `packages/schema`. The narrative model lands under
**For developers → Messages → Unified model** in a later phase.
